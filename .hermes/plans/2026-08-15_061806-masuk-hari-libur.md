# Masuk Hari Libur Implementation Plan

> **For Hermes:** Use Claude Code/subagent-driven development to implement this plan task-by-task, then independently review all diffs and real test output.

**Goal:** Owner/Mandor dapat mengaktifkan karyawan yang mendadak masuk pada hari libur, mengirim kode absen pribadi, mempertahankan status hari sebagai libur, dan membayar 1× gaji harian + uang makan dengan aturan/potongan absensi normal.

**Architecture:** Simpan otorisasi masuk hari libur secara terpisah dari `jadwal_libur`, karena hari tersebut tetap merupakan hak libur dan tidak boleh diubah menjadi hari kerja biasa. Otorisasi berlaku per user+tanggal dan menjadi syarat pembuatan/penampilan kode pada hari libur. Absensi tetap memakai alur normal, tetapi diberi penanda kerja hari libur dan komponen upah hari libur yang dapat diaudit.

**Tech Stack:** Laravel 13, PHP 8.3, Blade, MySQL, TelegramService, standalone PHP regression tests.

---

## Keputusan bisnis terkunci

1. Hari tetap dihitung sebagai hari libur; jatah libur tidak dibatalkan atau dipindahkan.
2. Bayaran kerja hari libur adalah 1× `gaji_harian` + uang makan.
3. Untuk pegawai harian, total bayaran hari itu tetap 1× gaji harian, bukan 2× akibat penjumlahan gaji reguler dan bonus yang sama.
4. Untuk pegawai bulanan, gaji bulanan tetap dan upah hari libur 1× gaji harian ditambahkan secara terpisah.
5. Aturan normal tetap berlaku: telat, laporan progress, lanjut kerja, pulang, dan potongan checkpoint.
6. Aktivasi hanya boleh dilakukan Owner (level 1) atau Supervisor/Mandor (level 3).
7. Kode tetap pribadi dan hanya valid untuk user terkait.
8. Kerja pada hari libur tidak menambah penyebut hari kerja dan tidak boleh membuat persentase kehadiran/KPI melebihi 100%.

## Temuan akar masalah

- `public/cron-kode-absen.php` sengaja melewati user jika `LiburService::isLibur()` bernilai true.
- `AbsensiController::kodeHariIni()` saat ini tetap memanggil `KodeAbsen::kodeHariIniUntuk()` untuk user libur, sehingga kode diam-diam dibuat.
- `resources/views/absensi/kode-hari-ini.blade.php` menyembunyikan kode tersebut dan hanya menampilkan label “Libur”.
- Ajuan Skip/Tukar Libur hanya menerima tanggal setelah hari ini sehingga tidak cocok untuk kejadian mendadak.
- Backend `koreksiManual()` ada, tetapi halaman rekap saat ini tidak menyediakan form tindakan manual yang mudah.

### Task 2: Endpoint Owner/Mandor untuk aktivasi kerja hari libur

**Objective:** Aktivasi aman, idempotent, hanya untuk user aktif yang memang libur hari ini.

**Files:**
- Modify: `routes/web.php`
- Modify: `app/Http/Controllers/AbsensiController.php`
- Test: `tests/kerja-hari-libur/test_aktivasi.php`

**Perilaku endpoint POST:**
1. Middleware auth + level 1/3.
2. Validasi user aktif, bukan Owner, dan `LiburService::isLibur(user, today()) === true`.
3. Tolak bila ada izin/sakit/cuti/dinas luar pada tanggal sama.
4. `firstOrCreate` otorisasi user+tanggal agar klik ulang tidak menggandakan data atau notifikasi.
5. Buat/ambil kode melalui `KodeAbsen::kodeHariIniUntuk()`.
6. Kirim kode ke Telegram karyawan jika terhubung; jika belum, tampilkan kode untuk disampaikan manual.
7. Catat siapa yang mengaktifkan.
8. Beri respons sukses yang jelas dan idempotent.

**Security checks:** CSRF, authorization server-side, user-specific code, tidak menerima nominal dari browser.

### Task 4: Integrasikan dengan alur absen normal dan penggajian

**Objective:** Kehadiran hari libur mengikuti semua checkpoint normal tetapi dibayar tepat satu kali.

**Files:**
- Modify: `app/Http/Controllers/AbsensiController.php`
- Modify: `app/Models/Absensi.php`
- Add migration/SQL idempotent untuk penanda/nominal audit jika dibutuhkan, misalnya `kerja_hari_libur` dan `upah_hari_libur` pada absensi
- Modify: `app/Services/GajiService.php`
- Modify: view slip/rekap yang menampilkan rincian pendapatan
- Tests: tambah tes pegawai harian dan bulanan

**Aturan perhitungan:**
- Absen masuk pada hari libur hanya boleh jika ada otorisasi hari itu.
- Status operasional tetap `hadir`/`telat`/`setengah_hari` agar alur checkpoint lama tidak pecah.
- Upah kerja hari libur dihitung dari snapshot 1× gaji harian, dikurangi potongan yang memang berlaku menurut alur normal.
- Uang makan memakai snapshot satu kali; jangan terhitung ganda.
- Pegawai harian: jangan menjumlahkan gaji reguler 1× dan upah hari libur 1× menjadi 2×.
- Pegawai bulanan: gaji pokok bulanan + upah hari libur 1×.
- Koreksi Owner harus dapat mengubah jam/status/potongan tanpa menghilangkan penanda kerja hari libur.

**Wajib telusuri semua mutator potongan:** absen masuk, auto-denda laporan progress, auto-denda kembali kerja, dan koreksi manual agar potongan tidak hanya mengurangi kolom gaji reguler yang bernilai nol pada hari libur.

## Risiko dan mitigasi

- **Bayaran ganda pegawai harian:** pisahkan konsep gaji reguler dan upah hari libur, tambah tes angka eksplisit.
- **Notifikasi ganda:** endpoint idempotent dan kirim hanya ketika row baru dibuat.
- **KPI >100%:** keluarkan kerja hari libur dari numerator reguler dan tambahkan tes.
- **Tombol salah tekan:** konfirmasi UI + audit `diaktifkan_oleh`; pembatalan tidak dibuat dulu (YAGNI) kecuali kebutuhan nyata muncul.
- **Izin bentrok:** validasi server-side sebelum aktivasi.
- **Pekerjaan Claude lama:** jangan reuse/menimpa sesi tmux `canopi` yang sedang memuat pekerjaan lain; mulai hanya setelah statusnya jelas dan Git tree aman.
